# 自动 PR Stack：本次文案审阅清单

本清单对应本次 PR 新增或修改的文案。`{变量}` 表示运行时替换的内容；实际示例使用 `#72 → #74`，箭头从下层指向上层。状态展示更新 PR 描述中的 Piper Progress，恢复记录复用原有 Bot 状态评论。

## Progress 状态

| 场景 | 原文或模板 |
| --- | --- |
| 已识别依赖 | `{#下层 → #上层} · 最终目标 {分支}` |
| 只有暂停原因、没有完整依赖链 | `自动 Stack` |
| 等待首次创建或顶部追加 | `已确认线性依赖，等待 Piper 建立或追加原生 Stack；完成前暂停集成。` |
| 已保存计划、尚未完成 | `Stack 尚未建立完成，Piper 将在队列重试或定时对账时继续；完成前暂停集成。` |
| Dry-run | `Stack Dry-run：仅预演，未修改 Base 或创建 Stack。请维护者检查日志后关闭 Dry-run。` |
| GitHub 拒绝操作 | `GitHub 未接受 Stack 操作。请维护者检查 Stack 冲突和 App 权限；Piper 会在后续对账中重试。` |
| 中断后暂停 | `Stack 已暂停：{原因} 请维护者核对 GitHub Stack 和分支状态。` |
| 检测到人工修改 | `检测到已管理的 Stack 被修改，已暂停自动操作。请维护者核对 GitHub Stack；如需手动接管，可关闭 stack.enabled。` |
| 开发者已有的 Stack | `已有 Stack 由开发者管理，Piper 不会自动追加。请维护者在 GitHub 确认新 PR 的归属。` |

继续使用原有检查项名称“Stack 依赖”、原有“等待下层 #72”等提示，以及原生 Stack 的位置、最终目标和直接父分支展示。此次修改后，存在暂停原因时不再追加“可独立集成”。

示例：

```text
#72 → #74 · 最终目标 dev

Stack 依赖：#72 → #74 · 最终目标 dev；已确认线性依赖，等待 Piper 建立或追加原生 Stack；完成前暂停集成；等待下层 #72
```

## 依赖核验失败

下列原因用于 Progress 中的 Stack 检查项；相关 PR 暂停集成。

| 场景 | 原文 |
| --- | --- |
| 无法确定最终目标 | `无法唯一确认最终目标分支。请维护者检查 PR 的 Base 和下层 PR 状态。` |
| 同一源分支有多个 PR | `同一源分支对应多个 PR，无法唯一确认依赖。请维护者检查重复 PR。` |
| Stack 信息未同步 | `GitHub 尚未返回完整 Stack。请等待 Stack 状态更新。` |
| Stack 接口不可用 | `无法读取 GitHub 原生 Stack。请维护者确认仓库支持 Stack 且 App 具备 Pull requests 读取权限。` |
| 分支与 PR 尚未同步 | `源分支与 PR 的 HEAD 尚未同步，等待 GitHub 更新后重新核验。` |
| 源分支丢失 | `源分支已删除或无法读取，已暂停自动 Stack。请维护者检查分支和 App 权限。` |
| Stack 更新、下层关闭或分支改变 | `Stack 正在更新，或下层 PR 已关闭、分支已改变。请等待 GitHub Restack；失败时由维护者检查 Stack。` |
| 无法读取目标或历史 | `无法核实目标分支或提交历史。请维护者检查分支是否存在及 App 读取权限。` |
| 多个 PR 指向相同 HEAD | `多个 PR 指向同一提交，无法唯一确认依赖。请维护者检查重复 PR。` |
| HEAD 分叉且共享未合入的历史 | `PR 共享尚未合入目标分支的历史，但当前 HEAD 已分叉。请维护者确认依赖，Piper 已暂停自动 Stack。` |
| 无法证明祖先关系 | `无法证明唯一的提交祖先关系。请维护者检查 Git 历史和 App 读取权限。` |
| 多个直接父节点 | `存在多个直接父 PR，已暂停自动 Stack。请维护者检查合流历史。` |
| 当前 Base 与父节点不符 | `当前 Base 与已证明的直接父 PR 不一致。请维护者确认分支关系；Piper 会保留当前 Base。` |
| 分叉 | `依赖图出现分叉，已暂停自动 Stack。请维护者确认各分支应如何组织。` |
| 超过读取范围 | `待核验 PR 超过 20 条，已暂停自动 Stack；请维护者缩小待处理范围。` |
| PR 与依赖图不同步 | `PR 或依赖图正在更新，请等待 Piper 重新核验。` |
| 恢复记录损坏 | `Stack 恢复回执不一致，请维护者检查原始 Bot 评论。` |

## 写入前中断的原因

这些原因会记录到既有 Bot 回执；后续 Progress 可通过“Stack 已暂停”模板展示。检查仍通过时，后续对账可继续操作。

| 场景 | 原文 |
| --- | --- |
| 依赖图改变 | `依赖图已改变，已暂停本次 Stack 操作。` |
| 已保存的快照失效 | `HEAD、Base 或依赖关系已改变，已保留当前分支并暂停 Stack 操作。` |
| 合并请求还在进行 | `下层 PR 的合并结果尚未确认，等待 GitHub 更新后再管理 Stack。` |
| 涉及多个 Stack | `依赖涉及多个已有 Stack，已暂停自动操作。` |
| PR 的即时状态改变 | `PR 在 Stack 操作前已改变，已暂停自动操作。` |
| 分支 HEAD 尚未同步 | `源分支已更新，等待 GitHub 同步 HEAD 后重试。` |
| 存在冲突 | `PR 存在冲突，已暂停自动 Stack。` |
| Base 链不完整 | `Stack 的 Base 链尚未就绪，已暂停创建。` |
| 恢复计划不一致 | `存在不一致的 Stack 恢复计划，请维护者检查 Bot 回执。` |

人工修改时使用上一节列出的“检测到已管理的 Stack 被修改”文案。

以下为内部诊断文本。Compare 异常通常映射到前述通用核验提示；PR 列表重复、同一 PR 出现在多个 Stack 等顶层异常也可显示在 Progress；冲突检查和 Stack 同步提示触发队列重试。这些诊断不单独新增评论：

- `GitHub Compare 返回了不一致的祖先关系。`
- `PR 列表不完整或重复。`
- `同一 PR 出现在多个 Stack 中。`
- `GitHub 尚未完成 Stack 冲突检查`
- `GitHub 尚未返回完整 Stack`

## 配置和部署说明

README 新增的完整说明见 [自动 Stack](../README.md#自动-stack)。本次修改原有原生 Stack 说明，将旧的“不创建、调整”描述替换为已实现的自动管理行为，并保留“Piper 不执行 Git Rebase、整组合并或管理 Merge Queue”。

新增字段说明：

| 字段 | 文案 |
| --- | --- |
| `stack.enabled` | 默认 `false`；开启 Git 历史依赖发现及原生 Stack 自动管理，按仓库启用 |
| `stack.dryRun` | 默认 `true`；仅记录拟调整的 Base 和拟创建或追加的 Stack；其他 Piper 功能仍按各自配置运行 |

App 事件订阅新增 `create`、`delete`，并补充：“已有 App 启用自动 Stack 时也需补选分支创建和删除事件。”

预约系统示例新增：

```yaml
stack:
  enabled: false # 按仓库启用自动依赖发现和原生 Stack 管理。
  dryRun: true # 检查日志后设为 false；仓库和 Worker 的 Dry-run 也须关闭。
```

README 同时说明了按仓库启用、三层 Dry-run、20 条候选 PR 上限、每条队列任务最多一步写入、逐步恢复、人工接管和 GitHub 接口不提供跨 PR 原子版本锁的限制。
